<div id="catching-regressions" className="my-10 scroll-mt-24">
  <h2 className="text-2xl sm:text-3xl font-bold tracking-tight text-slate-900 dark:text-slate-100 mb-3">

  <p className="text-sm sm:text-base text-slate-600 dark:text-slate-300 leading-relaxed mb-4">
    To prove Keploy catches real-world regressions, let&apos;s mutate <code>handler.go</code>. In the response struct, rename <code>json:&quot;url&quot;</code> to <code>json:&quot;short_url&quot;</code>:
  </p>

  <CodeBlock
    title="handler.go (Mutated)"
    language="go"
    showLineNumbers={true}
    code={`type successResponse struct {
    TS  int64  \`json:"ts"\`
    URL string \`json:"short_url"\` // Mutated: changed "url" to "short_url"
}`}
  />

  <p className="text-sm text-slate-600 dark:text-slate-300 my-3">
    Recompile and rerun the test suite against our recorded contract:
  </p>

  <CodeBlock
    title="Ubuntu (WSL2)"
    language="bash"
    code={`CGO_ENABLED=0 go build -o echo-psql-url-shortener .
keploy test -c "./echo-psql-url-shortener" --delay 10 --api-key "kep_YOUR_KEY"`}
  />

  <Callout type="danger" title="Regression Caught Instantly">
    Keploy immediately flags <code>post-url-1</code> as <strong>FAILED</strong> with <code>SCHEMA_BROKEN</code>. It highlights the exact mismatch: expected key <code>&quot;url&quot;</code> was missing in actual response, and unexpected key <code>&quot;short_url&quot;</code> was returned. No manual assertion had to be written!
  </Callout>

  <p className="text-sm text-slate-600 dark:text-slate-300 my-3">
    Undo the mutation to restore 100% test pass rate:
  </p>
  <CodeBlock
    title="Ubuntu (WSL2)"
    language="bash"
    code={`git checkout handler.go
CGO_ENABLED=0 go build -o echo-psql-url-shortener .
keploy test -c "./echo-psql-url-shortener" --delay 10 --api-key "kep_YOUR_KEY"`}
  />

  <h3 className="text-lg font-bold text-slate-900 dark:text-slate-100 mt-6 mb-2">
    Handling Volatile Values with assertions.noise
  </h3>
  <p className="text-sm text-slate-600 dark:text-slate-300 leading-relaxed mb-3">
    What happens if your API returns dynamic timestamps, UUIDs, or random tokens? In strict mode, differing timestamps would cause false positives. Keploy solves this with the <code>assertions.noise</code> configuration:
  </p>

  <CodeBlock
    title="keploy/test-set-0/tests/post-url-1.yaml"
    language="yaml"
    code={`assertions:
  noise:
    - body.ts      # Ignores dynamic Unix millisecond timestamp
    - header.Date  # Ignores HTTP server Date header`}
  />

  <p className="text-sm text-slate-600 dark:text-slate-300 mt-2">
    With <code>assertions.noise</code> applied, Keploy validates that the field <em>exists</em> and maintains the correct type (e.g. integer or RFC1123 date string) without requiring the dynamic value to match verbatim.
  </p>
