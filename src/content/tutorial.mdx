{/* Unique Introduction */}
Integration testing backend microservices usually forces developers into a frustrating tradeoff: spin up heavy Docker containers with brittle database seeds in CI, or burn hours maintaining hand-written mocks that quietly drift away from production schemas.

While evaluating Keploy for Go APIs, I tested a live **Echo REST application backed by PostgreSQL** directly on a Windows development workstation. Rather than requiring intrusive code instrumentation or custom test interfaces, Keploy attaches non-invasive **eBPF probes** directly to the Linux kernel network layer — recording live HTTP requests and binary PostgreSQL wire-protocol frames as you call your endpoints.

<Callout type="info" title="How Keploy Intercepts Traffic">
  Keploy uses Linux eBPF (extended Berkeley Packet Filter) to observe network traffic at the kernel socket layer. </Callout>

{/* Sub-section: The Bug That Taught Me the Most */}
<h3 id="the-bug-that-taught-me-the-most" className="group flex scroll-mt-24 items-center gap-2 font-serif font-semibold tracking-tight mt-10 mb-3 text-xl text-[#1D1B18] dark:text-[#FAF8F4]">
  5. The Loopback Bug &amp; Catching Breaking Schema Changes
  <a href="#the-bug-that-taught-me-the-most" aria-label="Link to section" className="text-[#B89B6A] dark:text-[#D9C6A5] opacity-0 group-hover:opacity-100 transition-opacity">#</a>
</h3>

My first run attempt failed with <code>connection refused at postgres:5432</code>. Here&apos;s the debugging trail, because I think it&apos;s more useful than a clean success story.

The cause: The sample&apos;s <code>main.go</code> was configured with <code>host=postgres</code>, which works when both app and database run inside Docker containers connected to the same Docker bridge network. But running the app binary <em>natively on WSL2</em> meant the Linux resolver had no idea what <code>postgres</code> was — only Docker containers get that internal DNS.

<Callout type="warning" title="Connection refused or missing mocks?">
  If you&apos;re on WSL2 and your app cannot reach Docker or your mocks come up empty, make sure the app connects to <code>host=localhost</code>. Running the binary natively while Docker exposes port 5432 places the traffic directly onto the Linux loopback interface where Keploy&apos;s eBPF hook can intercept TCP packets cleanly.
</Callout>

Switching to <code>host=localhost</code> fixed the connection immediately. Next, to test Keploy&apos;s regression detection, I mutated <code>handler.go</code>: changing the JSON struct tag from <code>json:&quot;url&quot;</code> to <code>json:&quot;short_url&quot;</code>:

<CodeBlock
  title="handler.go (Mutated for regression testing)"
  language="go"
  showLineNumbers={true}
  code={`type successResponse struct {
    TS  int64  \`json:"ts"\`
    URL string \`json:"short_url"\` // Changed from "url" to "short_url"
}`}
/>

After rebuilding with <code>CGO_ENABLED=0 go build -o echo-psql-url-shortener .</code>, running <code>keploy test</code> immediately flagged <code>SCHEMA_BROKEN</code>:

<CodeBlock
  title="Keploy regression report output"
  language="bash"
  code={`Test run failed:
  Testcase: post-url-1
  Diff:
    - Expected: {"url":"http://localhost:8082/1"}
    + Actual:   {"short_url":"http://localhost:8082/1"}
  Category: SCHEMA_BROKEN`}
/>

That proved Keploy catches contract regressions without needing hand-written test assertions. Finally, handling dynamic fields: timestamps in <code>body.ts</code> and HTTP <code>header.Date</code> legitimately change every run. Keploy&apos;s <code>assertions.noise</code> list is built exactly for this:

<CodeBlock
  title="keploy/test-set-0/tests/post-url-1.yaml"
  language="yaml"
  code={`assertions:
  noise:
    - body.ts
    - header.Date`}
/>

With dynamic fields placed in the noise list, the test suite verifies structural schema correctness and passes completely.
